Angular 22+ — règles essentielles

Support complémentaire de l’infographie. Référentiel pédagogique actualisé au 23/09/2026.

1. ⚡ État réactif → Signals

Pour l’état synchrone consommé par l’UI, privilégier les Signals.

products = signal<Product[]>([]);

total = computed(() =>
  this.products().length
);

RxJS reste pertinent pour les streams, événements et compositions asynchrones.

2. 🌐 Données asynchrones → Signals

Pour exposer à l’UI une donnée issue d’un Observable, toSignal() évite de gérer manuellement la souscription.

products = toSignal(products$);

httpResource() fournit une API réactive autour de HttpClient, avec réponse et état de requête sous forme de Signals.

userId = input.required<string>();
user = httpResource(() => `/api/users/${this.userId()}`);

Important : httpResource() est destiné aux lectures. Pour les mutations comme POST/PUT, Angular recommande d’utiliser directement HttpClient.

3. 📦 Découper l’application en chunks

loadComponent() et loadChildren() permettent le lazy loading des routes et produisent des chunks chargés à la demande.

export const routes: Routes = [
  {
    path: 'products',
    loadComponent: () =>
      import('./products/products.component')
        .then(m => m.ProductsComponent)
  },
  {
    path: 'admin',
    loadChildren: () =>
      import('./admin/admin.routes')
        .then(m => m.ADMIN_ROUTES)
  }
];

Cette approche est compatible avec une architecture Standalone ou NgModule.

4. 🧩 Standalone Components

Standalone simplifie la gestion des dépendances : elles sont déclarées au niveau du composant.

@Component({
  standalone: true,
  imports: [ReactiveFormsModule, MatFormFieldModule]
})
export class ProductForm {}

Standalone ne dicte pas l’arborescence du projet. Une organisation par features reste parfaitement possible :

app/
├── products/
│   ├── pages/
│   ├── components/
│   ├── services/
│   └── products.routes.ts
├── users/
│   ├── pages/
│   └── components/
└── app.routes.ts

Pour du nouveau code, Angular recommande les composants standalone plutôt que les NgModules.

5. 💉 DI moderne

@Service()
export class ProductService {
  private http = inject(HttpClient);
}

À connaître également : l’approche historique @Injectable({ providedIn: 'root' }) et l’injection par constructeur restent rencontrées dans les projets existants.

6. 🎨 Templates modernes

@if (user()) {
  <p>{{ user().name }}</p>
}

@for (product of products(); track product.id) {
  <app-product [product]="product" />
}

@switch (status()) {
  @case ('loading') { ... }
  @case ('success') { ... }
}

Cette syntaxe remplace progressivement les anciennes formes structurelles comme *ngIf et *ngFor.

7. 📝 Forms — choisir selon le contexte

Template-driven

Simple, adaptée aux formulaires très basiques.

Reactive Forms

Modèle explicite, robuste, scalable et testable ; Angular la recommande lorsque les formulaires sont importants dans l’application.

Signal Forms

Particulièrement adaptées aux nouvelles applications construites avec Signals.

Documentation Angular au 23/09/2026 : Signal Forms work best in new applications built with signals. Pour une application existante utilisant Reactive Forms, ou lorsqu’on recherche des garanties de stabilité en production, Reactive Forms reste un choix solide.

Retour terrain : à ce jour, le REX et les cas d’usage sont encore moins nombreux sur Signal Forms, notamment pour les formulaires dynamiques, même si ces scénarios sont couverts par la documentation.

8. 🔌 API des composants

name = input<string>();
changed = output<string>();
value = model<string>();

Ces APIs modernes remplacent progressivement les décorateurs @Input() / @Output() et certains patterns basés sur EventEmitter.
