1Créer un composant

Un composant, c'est une classe TypeScript décorée par @Component. Le décorateur donne au minimum un selector (le nom de la balise HTML) et un template (ce qui s'affiche).

En 1 fichier (template inline)

import { Component } from '@angular/core';

@Component({
  selector: 'app-hello',
  template: `<h1>Bonjour {{ name }}</h1>`,
})
export class Hello {
  name = 'Angular';
}

En 3 fichiers (ts + html + css)

@Component({
  selector: 'app-hello',
  templateUrl: './hello.html',
  styleUrl: './hello.css',
})
export class Hello {
  name = 'Angular';
}

Même composant, le HTML et le CSS vivent dans leurs propres fichiers. C'est ce que génère la commande ng generate component hello (raccourci ng g c hello).

À retenir @Component({ selector, template }) + export class. Un ou trois fichiers, c'est un choix de confort : inline pour un petit composant, séparé dès que le HTML grandit. Plus besoin d'écrire standalone: true, c'est le défaut.

2Utiliser un composant

Pour afficher un composant dans un autre, le parent fait deux choses : il l'importe dans son tableau imports, puis il écrit sa balise dans son template.

import { Component } from '@angular/core';
import { Hello } from './hello/hello';

@Component({
  selector: 'app-root',
  imports: [Hello],                      // 1. on déclare ce qu'on utilise
  template: `
    <h1>Mon application</h1>
    <app-hello />                        <!-- 2. on pose la balise -->
  `,
})
export class App {}
À retenir Oublier l'imports est l'erreur n°1 : la balise reste inconnue et Angular affiche 'app-hello' is not a known element. La balise peut être auto-fermante (<app-hello />).

3Anatomie d'un composant et arbre de composants

Une application Angular est un arbre : un composant racine (App) qui utilise des composants, qui en utilisent d'autres. Chaque nœud de l'arbre a la même anatomie.

L'anatomie

MorceauRôle
selectorle nom de la balise, préfixé (app-)
importsles composants, directives et pipes utilisés dans le template
template / templateUrlle HTML affiché
styles / styleUrlle CSS, isolé au composant
la classeles données et les méthodes que le template utilise

L'arbre

À retenir Découper l'écran en composants, c'est tout le travail Angular. Règle simple : un bloc qui se répète ou qui a sa propre logique devient un composant.

4Réactivité : les signals

Un signal est une valeur que le template surveille. On la lit avec des parenthèses, on la change avec set ou update, et l'affichage se met à jour tout seul.

import { Component, signal } from '@angular/core';

@Component({
  selector: 'app-counter',
  template: `
    <p>Compteur : {{ count() }}</p>
    <button (click)="increment()">+1</button>
  `,
})
export class Counter {
  count = signal(0);                 // créer

  increment() {
    this.count.update(c => c + 1);  // modifier à partir de l'ancienne valeur
    // this.count.set(0);          // ou remplacer
  }
}
ÉcritureEffet
count()lire (dans la classe comme dans le template)
count.set(5)remplacer
count.update(c => c + 1)calculer la nouvelle valeur à partir de l'ancienne
À retenir Dès qu'une donnée peut changer pendant que la page est affichée, mettez-la dans un signal(). Ce n'est que le début : on peut dériver des valeurs (computed), réagir aux changements (effect), lier des signals entre eux (linkedSignal)… c'est le parcours avancé du lab.

5Flux parent / enfant : input() et output()

Les données descendent du parent vers l'enfant avec input(). Les événements remontent de l'enfant vers le parent avec output(). Jamais l'inverse.

L'enfant déclare

import { Component, input, output } from '@angular/core';

@Component({
  selector: 'app-formation-card',
  template: `
    <h3>{{ formation().titre }}</h3>
    <button (click)="onInscrire()">S'inscrire</button>
  `,
})
export class FormationCard {
  formation = input.required<Formation>();  // ⬇ reçoit
  inscrire = output<number>();              // ⬆ émet

  onInscrire() {
    this.inscrire.emit(this.formation().id);
  }
}

Le parent branche

<!-- dans le template du parent -->
@for (f of formations(); track f.id) {
  <app-formation-card
    [formation]="f"
    (inscrire)="ajouterAuPanier($event)" />
}

Et les variables réactives ?

Un input() est un signal : on le lit avec formation(), et si le parent change la valeur, l'enfant se met à jour. On ne le modifie jamais depuis l'enfant (il est en lecture seule) : pour remonter un changement, on émet avec output().

À retenir input.required<T>() pour recevoir, output<T>() + .emit() pour prévenir. Dans le parent, $event contient ce qui a été émis.

6Les mécanismes de template, très basique

Le template, c'est du HTML plus quelques écritures qui le relient à la classe. Les voici, toutes.

ÉcritureExempleCe que ça fait
Interpolation{{ formation().titre }}affiche une valeur de la classe
Liaison de propriété<img [src]="url" />donne une valeur à un attribut, un input…
Liaison d'événement<button (click)="save()">appelle une méthode sur un événement
Condition@if (ok()) { … } @else { … }affiche ou non un bloc
Boucle@for (f of items(); track f.id) { … } @empty { … }répète un bloc ; track est obligatoire
Pipe{{ prix | currency:'EUR' }}formate une valeur à l'affichage
Classe / style conditionnel[class.actif]="selected()"ajoute une classe selon une condition

Il existe aussi des directives (des comportements qu'on pose sur une balise, par exemple routerLink en section 9) et des pipes personnalisés : vous les rencontrerez dans Housing.

À retenir Crochets = je donne, parenthèses = j'écoute, {{ }} = j'affiche, @if / @for = je contrôle. Les anciennes écritures *ngIf / *ngFor existent encore dans les projets, elles font la même chose.

7Comment fonctionne un composant, et les services

Avec les sections précédentes on peut maintenant voir le composant en entier : une classe et un template qui se parlent dans les deux sens.

Entre deux composants, on a vu input() / output() (section 5). Mais ça ne marche qu'entre un parent et son enfant direct. Pour partager une donnée ou une logique entre composants éloignés, ou simplement sortir du composant ce qui n'est pas de l'affichage, on passe par un service.

import { Injectable } from '@angular/core';

@Injectable({ providedIn: 'root' })   // 1 seule instance pour toute l'app
export class FormationService {
  getAll(): Formation[] {
    return FORMATIONS;
  }
}
import { Component, inject } from '@angular/core';

export class FormationList {
  private service = inject(FormationService);  // on demande, Angular fournit
  formations = this.service.getAll();
}

Un service sert à bien d'autres choses : appeler une API HTTP, garder un état partagé (le panier), encapsuler une règle métier. Règle simple : un composant affiche, un service sait.

À retenir @Injectable({ providedIn: 'root' }) sur le service, inject(MonService) dans celui qui l'utilise. Deux composants qui injectent le même service partagent la même instance : c'est ainsi qu'ils communiquent sans être parent et enfant.

8Le cycle de vie, en un schéma

Angular crée le composant, l'affiche, le met à jour quand ses signals changent, puis le détruit quand il quitte l'écran. On peut s'y brancher avec des hooks ; le seul à connaître pour l'instant est ngOnInit.

import { Component, OnInit, input } from '@angular/core';

export class FormationDetail implements OnInit {
  id = input.required<number>();

  ngOnInit() {
    // ici, this.id() a sa valeur : c'est le bon endroit pour charger des données
  }
}
À retenir Initialiser dans ngOnInit, pas dans le constructeur (les input() n'y sont pas encore). Avec les signals, inject() et input(), on a de moins en moins besoin des autres hooks : on verra plus tard comment maîtriser ce cycle (effect, afterRenderEffect, DestroyRef).

9Le routing, simplement

Le routeur fait correspondre l'URL à un composant, et l'affiche à la place de <router-outlet />. Trois pièces : la liste des routes, l'outlet, les liens.

// app.routes.ts
import { Routes } from '@angular/router';

export const routes: Routes = [
  { path: '',            component: Home },
  { path: 'details/:id', component: Details },
];

// app.config.ts : provideRouter(routes)   (déjà fait par ng new)
// App : l'outlet et les liens
@Component({
  selector: 'app-root',
  imports: [RouterOutlet, RouterLink],
  template: `
    <nav><a routerLink="/">Accueil</a></nav>
    <router-outlet />
  `,
})
export class App {}
// Details : lire le paramètre de l'URL
export class Details {
  private route = inject(ActivatedRoute);
  id = Number(this.route.snapshot.params['id']);
}

Avec routerLink, la page ne se recharge pas : c'est le principe d'une application monopage. Pour un lien dynamique : [routerLink]="['/details', f.id]".

À retenir routes = la carte, <router-outlet /> = l'emplacement, routerLink = le lien. Le paramètre :id se lit via ActivatedRoute.
